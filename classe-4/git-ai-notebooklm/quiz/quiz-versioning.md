## 1. Le domande

1. Che differenza c'e tra Git e GitHub?
   1. Git e lo strumento che tiene la storia del progetto; GitHub e il servizio online dove i progetti vivono e si condividono.
   2. Sono la stessa identica cosa con due nomi.
   3. Git e un sito web; GitHub e un programma da installare.
   4. Git serve per le foto; GitHub per i video.
2. Che cos'e un commit?
   1. Un salvataggio del progetto (una "fotografia") con un messaggio che descrive il cambiamento.
   2. La cancellazione di tutti i file.
   3. Il nome del proprietario del progetto.
   4. Un errore di sistema.
3. Che cos'e un branch (ramo)?
   1. Una strada di lavoro parallela per provare senza rovinare la versione principale.
   2. Il cestino del progetto.
   3. Il pulsante per stampare.
   4. Un tipo di immagine.
4. Cosa propone una Pull Request?
   1. Di unire il proprio ramo alla versione principale, dopo una revisione.
   2. Di cancellare il repository.
   3. Di cambiare la password.
   4. Di spegnere il computer.
5. Nel numero di versione 1.2.3, la prima cifra (major) aumenta quando…
   1. si fa un cambiamento grosso, magari incompatibile con il vecchio.
   2. si corregge un piccolo errore.
   3. si cambia il colore dell'icona.
   4. non aumenta mai.
6. Nel numero di versione 1.2.3, la terza cifra (patch) aumenta quando…
   1. si corregge solo un bug, senza novita.
   2. si riscrive tutto da capo.
   3. si aggiunge una grande funzione nuova.
   4. si cancella il progetto.
7. Qual e la regola d'oro del versioning?
   1. Una versione gia pubblicata non si riusa: prima si aumenta il numero, poi si pubblica.
   2. Si puo cambiare una versione pubblicata quando si vuole.
   3. Il numero di versione si sceglie a caso.
   4. Le versioni non servono a niente.
8. Che cos'e un merge?
   1. Unire un ramo con quello principale (main).
   2. Spegnere il progetto.
   3. Un tipo di file audio.
   4. La cancellazione della storia.
9. Che cos'e un revert?
   1. Un nuovo commit che annulla uno sbagliato, senza cancellare la storia.
   2. La formattazione del disco.
   3. Il ripristino della password.
   4. Un ramo abbandonato.
10. Quando avviene un conflitto di merge?
    1. Quando due rami hanno cambiato la stessa riga in modo diverso.
    2. Quando il computer e spento.
    3. Quando manca la corrente.
    4. Quando il file e troppo grande.
11. Che tipo di servizio e GitHub?
    1. PaaS (una piattaforma online gia pronta).
    2. Un videogioco.
    3. Un programma di disegno.
    4. Un antivirus.
12. Con quale modello si paga GitHub?
    1. Freemium: base gratis, funzioni avanzate a pagamento.
    2. Solo a pagamento, sempre.
    3. Non esiste, e vietato.
    4. Si paga a ore.
