Dispensa 6 — Lavoriamo come un'azienda

Classe 3 · Informatica · 08/10/2026 · il gioco della classe: fork, Pull Request, merge, versioni · italiano
Cosa facciamo oggi: costruiamo tutti insieme un gioco per il telefono, come si fa nelle aziende di software. Il lavoro è diviso in pezzi: ognuno fa il suo, lo propone con una Pull Request, il prof lo unisce (merge) e alla fine esce una versione nuova del gioco, con dentro il lavoro di tutti.

1. I ruoli, come in un'azienda

RuoloChiCosa fa
Product owneril profdecide cosa entra in ogni versione e fa il merge
Project manageruno per squadra, a turnotiene la lista dei lavori della squadra e apre la Pull Request di squadra
Sviluppatorituttifanno il proprio pezzo e lo propongono
Revisoreil controllo automatico + un compagnoguarda la modifica prima del merge

2. Il primo lavoro di tutti: il tuo mostro

RIQUADRO 11 — il tuo mostro (cambia i valori!)
{
  "nome": "Gnam Gnam",
  "colore": "#ff6fb1",
  "occhi": 3,
  "corna": 1,
  "bocca": 0,
  "velocita": 2,
  "frase": "Ti mangio il Wi-Fi!",
  "immagine": false
}
Il file si chiama come il tuo PC, sempre con due cifre: PC 7 → pc07.json, PC 14 → pc14.json, dentro la cartella mostri. Sulla pagina della classe scegli il tuo PC: il nome del file è già pronto da copiare.
1Apri la cartella dei mostri

Entra su github.com con il TUO account e apri la cartella dei mostri (sulla pagina della classe c'è il bottone): https://github.com/nicolaregge-pulse/corso-informatica/tree/main/docs/giochi/assalto-dei-mostri/mostri.

2Crea il file

Sopra l'elenco dei file: bottone grigio Add file → Create new file. GitHub ti dice che serve una copia tua: premi il bottone verde Fork this repository (crea la tua copia).

3Nome e contenuto

Nel campo del nome incolla il TUO nome di file (es. pc14.json). Nel riquadro grande incolla il RIQUADRO 11.

4Fallo tuo

Cambia nome, colore, occhi (1-3), corna (0-1), bocca (0-2), velocità (1-3) e la frase che grida. Lascia le virgolette e le virgole come sono.

5Proponi la modifica

Bottone verde Commit changes... → nella finestra bottone verde Propose changes (proponi). Poi bottone verde Create pull request, e ancora Create pull request.

6Il controllo automatico

Aspetta un minuto nella pagina della tua Pull Request: compare una spunta verde (tutto a posto) o una X rossa. Con la X, clic su Details: c'è scritto cosa sistemare (di solito una virgola). Sistema il file nella tua copia: la Pull Request si aggiorna da sola.

7Il merge

Il prof guarda la tua Pull Request e la unisce al gioco. Quando è viola con scritto Merged: FATTO! Il tuo mostro è nel gioco. Apri https://nicolaregge-pulse.github.io/corso-informatica/giochi/assalto-dei-mostri/ e cercalo nell'elenco dei mostri della classe.

3. Il lavoro di squadra

SquadraFileCosa cambia
REGOLEregole.jsonquanti colpi regge il vetro, quanto in fretta sparano i mostri, i punti
GRAFICAgrafica.jsoni colori della città: cielo, luna, palazzi, finestre, strada
TESTItesti.jsonil titolo, le frasi di fine partita, i messaggi (anche nella tua lingua)
SUONIsuoni.jsonil volume e le note della musica di vittoria
8Squadra

Il project manager scrive su un foglio la lista dei lavori della squadra (il backlog): chi fa cosa e entro quando.

9Squadra

La squadra decide su carta i valori nuovi (colori, frasi, regole).

10Squadra

Il project manager apre il file della squadra nella cartella del gioco (https://github.com/nicolaregge-pulse/corso-informatica/tree/main/docs/giochi/assalto-dei-mostri), lo cambia con la matita e fa la Pull Request, come per il mostro. Negli autori scrive solo i numeri dei PC.

11Squadra

Un compagno di un'altra squadra fa la revisione: nella Pull Request, scheda Files changed, guarda le modifiche e scrive un commento.

Il conflitto: se due persone cambiano la stessa riga dello stesso file, GitHub non sa quale tenere. Non è un disastro: succede in tutte le aziende. Il prof ve lo fa vedere alla lavagna e lo risolve con voi.

4. La versione nuova e il grafico

12La release

Quando i lavori sono uniti, il prof pubblica la release «assalto-v1.1» (i mostri della classe) e poi la «assalto-v1.2» (le squadre). Il numero in basso a destra nel gioco cambia.

13Il grafico delle versioni

Nel repository del corso: scheda Insights → a sinistra Network. Vedi tutte le copie (fork), i commit e i merge: è la storia del lavoro di tutti.

Carta e penna: disegna il grafico delle versioni del gioco: la linea principale (main) da v1.0 a v1.2, la tua copia che parte, il tuo commit, la freccia del merge che torna nella linea principale.

5. Le parole del mestiere

ParolaCosa vuol dire
Repositoryla cartella del progetto su GitHub, con tutta la sua storia
Forkla TUA copia del repository: lavori lì senza toccare l'originale
Commituna modifica salvata, con il suo messaggio
Pull Requestla proposta: «prof, unisci la mia modifica al gioco»
Revisionequalcuno (o il controllo automatico) guarda la modifica prima di unirla
Mergeunire la modifica al progetto
Conflittodue persone hanno cambiato la stessa riga: bisogna scegliere
Issueun lavoro da fare, scritto nella lista del progetto (il backlog)
Releaseuna versione finita e numerata del gioco: v1.0, v1.1, v1.2
