Il Versioning — 5 livelli · ভার্সনিং — ৫টি স্তর

Classe 3 · Informatica · dalla versione singola fino a branch, merge e release in team · bilingue IT / বাংলা

Livello 1 · স্তর ১ — La versione (il numero)
Ogni salvataggio importante prende un numero: v1.0. Se lo correggi diventa v1.1. Il numero dice a che punto sei.
Esempio: consegni un documento → v1.0; lo sistemi → v1.1.
প্রতিটি গুরুত্বপূর্ণ সেভের একটি নম্বর থাকে: v1.0। ঠিক করলে হয় v1.1। নম্বর বলে দেয় তুমি কোন পর্যায়ে আছ।
উদাহরণ: একটি ডকুমেন্ট জমা দিলে → v1.0; ঠিক করলে → v1.1।
Livello 2 · স্তর ২ — Major . minor . patch
vX.Y.Z: X = cambiamento grosso (incompatibile), Y = nuova funzione, Z = correzione (bug).
Esempio (un gioco): v1.0.0 giocabile → v1.1.0 (aggiungi i suoni) → v1.1.1 (correggi un bug) → v2.0.0 (nuovo motore, tutto cambiato).
vX.Y.Z: X = বড় পরিবর্তন, Y = নতুন ফিচার, Z = বাগ ঠিক করা।
উদাহরণ (একটি গেম): v1.0.0 (খেলা যায়) → v1.1.0 (সাউন্ড) → v1.1.1 (বাগ ঠিক) → v2.0.0 (নতুন ইঞ্জিন)।
Livello 3 · স্তর ৩ — La storia dei commit
Non conta solo il numero finale: ogni modifica è un commit con un messaggio, in sequenza. Puoi tornare a qualsiasi punto.
শুধু শেষ নম্বর নয়: প্রতিটি পরিবর্তন হলো বার্তাসহ একটি commit, ক্রমানুসারে। তুমি যেকোনো বিন্দুতে ফিরে যেতে পারো। (উপরের চেইনটি দেখো: "মেনু" → "স্কোর" → "গ্রাফিক্স" → "অডিও"।)
Livello 4 · স্তর ৪ — Branch e merge (linee parallele)
Mentre il main (stabile) va avanti, apri un branch per una funzione o un bugfix senza rompere il main; poi lo unisci (merge).
Esempio: main a v1.0; il branch hotfix corregge un bug e si fonde subito (v1.0.1); il branch audio aggiunge i suoni e si fonde dopo (v1.1).
main (স্থিতিশীল) চলার সময়, main নষ্ট না করে একটি ফিচার/বাগফিক্সের জন্য একটি branch খোলো; পরে merge করো।
উদাহরণ: main v1.0-এ; hotfix branch বাগ ঠিক করে সাথে সাথে merge (v1.0.1); audio branch পরে merge (v1.1)।
Livello 5 · স্তর ৫ — Release, tag e collaborazione (in team)
Più persone lavorano insieme: ognuno sul suo branch → Pull Request (proposta) → revisione → merge → si tagga una Release (es. v2.0).
Esempio: un team di 3 sul gioco — uno fa i livelli, uno l'audio, uno i bug; ognuno apre una Pull Request, si controlla e si fa merge; alla fine si pubblica la Release v2.0 "multiplayer".
একাধিক ব্যক্তি একসাথে কাজ করে: প্রত্যেকে নিজের branch-এ → Pull Request → রিভিউ → merge → একটি Release ট্যাগ করা হয় (যেমন v2.0)।
উদাহরণ: গেমে ৩ জনের দল — একজন লেভেল, একজন অডিও, একজন বাগ; প্রত্যেকে একটি Pull Request খোলে, রিভিউ করে merge হয়; শেষে Release v2.0 "মাল্টিপ্লেয়ার" প্রকাশ করা হয়।
