Il mio GitHub in ordine

Il tuo repository «lazarus» deve essere come una libreria: una cartella per ogni progetto e, nella pagina principale, solo il README e le cartelle.

1. Controlla il tuo repository

Scegli il tuo nome. La pagina guarda il tuo GitHub e ti dice che cosa va bene e che cosa manca.

Che cosa c'è adesso nel tuo repository (in rosso quello che va tolto o spostato)

Come deve diventare

lazarus/ ├── README.md ← chi sei e i tuoi progetti ├── primo-programma/ ← il primo progetto (.lpi .lpr .pas .lfm) └── salvadanaio/ ← il salvadanaio (.lpi .lpr .pas .lfm)

Niente file .exe: non servono, basta il progetto. Ogni nuovo progetto Lazarus avrà la sua cartella.

Quali file di Lazarus portare su GitHub

Guarda l'estensione: sono le lettere dopo il punto nel nome del file. Su GitHub portiamo solo i file che servono a riaprire il progetto in Lazarus.

EstensioneChe cos'èSu GitHub?
.lpiil progetto: si apre con Lazarus✔ sì
.lpril programma principale✔ sì
.pas (o .pp)il codice che hai scritto (le unit)✔ sì
.lfmla finestra (form) con bottoni e caselle✔ sì
.ico .pngl'icona e le immagini, se le hai scelte✔ sì
.inc .lpkfile aggiunti da te (raro, per i più esperti)✔ sì
.exeil programma già pronto: Lazarus lo rifà quando premi Esegui✘ no
.lpsla «sessione»: quali file avevi aperto e dove era il cursore. È solo tua✘ no
.res .o .ppu .compiled .rstfile che Lazarus si crea da solo quando compila✘ no
.bak e i file che finiscono con ~copie di sicurezza dell'editor✘ no
cartelle lib e backupcopie e file di lavoro di Lazarus✘ no

Regola facile: carica solo i file .lpi, .lpr, .pas, .lfm (e .ico).

2. Fai quello che manca

Fai solo il passo che ti dice il riquadro blu qui sopra. Poi aspetta 2-3 minuti e ricarica la pagina con F5: il controllo si aggiorna.

Passo A · Apri il tuo repository

  1. Apri github.com e fai l'accesso.
  2. In alto a sinistra clicca sul tuo repository lazarus.

Passo B · Crea la cartella «primo-programma» e carica il primo programma

  1. Sul PC apri la cartella dove hai il tuo primo programma Lazarus.
  2. Su GitHub, nel repository, clicca il bottone Add file (in alto a destra), poi Upload files.
  3. Trascina nella pagina la cartella intera del primo programma. Se la cartella non si chiama «primo-programma», prima rinominala sul PC.
  4. In fondo clicca il bottone verde Commit changes.

Passo C · Cancella i file sparsi nella pagina principale

  1. Nella pagina principale del repository clicca un file sparso (per esempio project1.lpi).
  2. In alto a destra clicca i tre puntini …, poi Delete file.
  3. Clicca il bottone verde Commit changes, poi ancora Commit changes.
  4. Torna alla pagina principale (clicca lazarus in alto) e rifai per il file successivo.

Prima il passo B, poi il C: cancella i file sparsi solo quando il progetto è già dentro la sua cartella. Se li hai già cancellati, niente paura: i file sono ancora sul tuo PC, caricali nella cartella con il passo B.

Compare un riquadro rosso «File could not be edited»? Vuol dire che quel file l'hai già cancellato prima: la pagina era vecchia. Clicca Cancel, premi F5 e passa al file successivo.

Passo D · Cancella i file .exe

  1. Apri la cartella dove c'è il file .exe e clicca il file .exe.
  2. In alto a destra …, poi Delete file, poi Commit changes due volte.

Passo E · Carica il salvadanaio nella cartella «salvadanaio»

  1. Sul PC trova la cartella del tuo salvadanaio (di solito Documenti). Se non si chiama «salvadanaio», rinominala.
  2. Su GitHub clicca Add file, poi Upload files.
  3. Trascina nella pagina la cartella intera «salvadanaio».
  4. Clicca il bottone verde Commit changes.

Passo F · Scrivi il tuo README

  1. Nella pagina principale clicca README.md, poi la matita in alto a destra.
  2. Scrivi almeno 4 righe: il tuo nome, la classe, e l'elenco dei progetti (primo-programma, salvadanaio).
  3. Clicca il bottone verde Commit changes, poi ancora Commit changes.

Se README.md non c'è: Add file → Create new file, nome README.md, scrivi e Commit changes.

Repository in ordine: bravo! Fallo vedere al tuo vicino.
