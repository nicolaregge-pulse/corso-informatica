FASE 1 — La teoria

In breve

  1. Il gioco della 3INF è un fork: una copia del gioco della 2INF che cresce per conto suo.

    ৩INF-এর খেলা একটি fork: ২INF-এর খেলার একটি কপি, যা নিজে নিজে বড় হয়।

  2. Il tuo Documento su Classroom è il TUO ramo: parte dalla versione del gioco che stai giocando.

    Classroom-এ তোমার ডকুমেন্ট হলো তোমার নিজের শাখা: তুমি খেলার যে সংস্করণ খেলছ, সেখান থেকে শুরু হয়।

  3. Ogni Pull Request che scrivi nel Documento è un pallino sul tuo ramo: una proposta di modifica.

    ডকুমেন্টে লেখা প্রতিটি Pull Request তোমার শাখার একটি বিন্দু: একটি পরিবর্তনের প্রস্তাব।

  4. Il prof la legge. SÌ: merge, la proposta entra nel gioco e nasce una versione nuova (v1.1, v1.2…). NO: resta sul tuo ramo e la puoi correggere.

    শিক্ষক এটি পড়েন। হ্যাঁ: merge, প্রস্তাবটি খেলায় ঢোকে এবং নতুন সংস্করণ হয় (v1.1, v1.2…)। না: এটি তোমার শাখায় থাকে, তুমি ঠিক করতে পারো।

  5. Senza Pull Request il tuo ramo è vuoto: nel gioco non entra niente di tuo.

    Pull Request ছাড়া তোমার শাখা খালি: খেলায় তোমার কিছুই ঢোকে না।

La lavagna del prof

Sulla linea rossa le versioni (v0.8, v0.9, v1.0). In blu il fork che parte dalla v0.9. Sul ramo, le Pull Request: quella accettata (ACCEPT ✓) rientra con il MERGE, quella rifiutata (REFUSE ✗) resta fuori.

লাল রেখায় সংস্করণ। নীল রঙে fork। শাখায় Pull Request: গৃহীত (ACCEPT ✓) MERGE দিয়ে ফিরে আসে, প্রত্যাখ্যাত (REFUSE ✗) বাইরে থাকে।

Come si chiede una modifica: il giro della Pull Request

Nel vostro gioco funziona come in un'azienda vera. Tu proponi, il programma automatico legge, il prof decide, la versione nuova esce.

তোমাদের খেলায় সত্যিকারের কোম্পানির মতো কাজ হয়। তুমি প্রস্তাব দাও, স্বয়ংক্রিয় প্রোগ্রাম পড়ে, শিক্ষক সিদ্ধান্ত নেন, নতুন সংস্করণ বের হয়।

  1. Tu scrivi la richiesta nel Modulo «Consegna» (o nel Documento): titolo, cosa cambia, dove, perché. Puoi aggiungere un'immagine.

    তুমি অনুরোধ লেখো «Consegna» ফর্মে (বা ডকুমেন্টে): শিরোনাম, কী বদলায়, কোথায়, কেন। ছবিও যোগ করতে পারো।

  2. Lo script gira da solo ogni 5 minuti: è un programma del prof su Google che legge le richieste nuove e le copia nel repository Git del corso, con il tuo nome e l'ora.

    স্ক্রিপ্ট নিজে নিজে চলে প্রতি ৫ মিনিটে: এটি Google-এ শিক্ষকের একটি প্রোগ্রাম, যা নতুন অনুরোধ পড়ে এবং তোমার নাম ও সময়সহ কোর্সের Git repository-তে কপি করে।

  3. Il prof (con l'intelligenza artificiale) legge la tua Pull Request e decide: SÌ o NO.

    শিক্ষক (কৃত্রিম বুদ্ধিমত্তার সাথে) পড়েন এবং সিদ্ধান্ত নেন: হ্যাঁ বা না।

  4. SÌ = merge: la modifica entra nel gioco, nasce una versione nuova (v1.5, v1.6…) e nel changelog c'è scritto il numero della tua Pull Request.

    হ্যাঁ = merge: পরিবর্তনটি খেলায় ঢোকে, নতুন সংস্করণ হয় এবং changelog-এ তোমার Pull Request-এর নম্বর লেখা থাকে।

  5. Tu controlli nel grafo delle versioni: il pallino nuovo è anche merito tuo. Se è NO, leggi il perché, correggi e rimanda.

    তুমি দেখো সংস্করণের গ্রাফে: নতুন বিন্দুটি তোমারও কৃতিত্ব। না হলে, কেন পড়ো, ঠিক করো এবং আবার পাঠাও।

Com'è fatta una Pull Request

Quattro parti, sempre, nel Modulo o nel Documento. Esempio vero: la Pull Request #1, entrata nel gioco con la v1.1.

সবসময় চারটি অংশ। সত্যিকারের উদাহরণ: Pull Request #1, যা v1.1-এ খেলায় ঢুকেছে।

Gli errori della settimana scorsa (e perché)

  1. Documento vuoto. Il tuo ramo resta vuoto: nel gioco non entra niente.

    খালি ডকুমেন্ট। তোমার শাখা খালি থাকে: খেলায় কিছুই ঢোকে না।

  2. Modello copiato senza cambiare le parole in MAIUSCOLO. La Pull Request non propone niente: il prof non può fare il merge.

    বড় হাতের শব্দ না বদলে নমুনা কপি করা। Pull Request কিছুই প্রস্তাব করে না: শিক্ষক merge করতে পারেন না।

  3. Lavoro scritto fuori dal Documento (un altro file, una chat). Il prof non lo vede: non diventa un pallino del tuo ramo.

    ডকুমেন্টের বাইরে লেখা কাজ (অন্য ফাইল, চ্যাট)। শিক্ষক এটি দেখেন না: এটি তোমার শাখার বিন্দু হয় না।

  4. Tutto in un unico testo, senza PR-1, PR-2, PR-3. Non si capisce quali sono le proposte: ognuna deve avere il suo numero.

    PR-1, PR-2, PR-3 ছাড়া সব এক লেখায়। কোনগুলো প্রস্তাব বোঝা যায় না: প্রতিটির নিজের নম্বর থাকতে হবে।
