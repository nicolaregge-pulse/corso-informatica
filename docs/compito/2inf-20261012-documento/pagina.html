In breve

  1. Il gioco della 2INF è il gioco ORIGINALE: la 3INF e la 1INF ne hanno fatto una copia (fork).

    2INF 的游戏是原版游戏：3INF 和 1INF 复制了它（fork）。

  2. Il tuo Documento su Classroom è il TUO ramo: parte dalla versione del gioco che stai giocando (v0.11).

    你在 Classroom 上的文档就是你自己的分支：它从你正在玩的游戏版本（v0.11）开始。

  3. Ogni Pull Request che scrivi è un pallino sul tuo ramo: una proposta di modifica.

    你写的每一个 Pull Request 都是你分支上的一个圆点：一个修改的建议。

  4. Il prof la legge. SÌ: merge, la proposta entra nel gioco e nasce una versione nuova (v0.12, v0.13…). NO: resta sul tuo ramo e la puoi correggere.

    老师会读它。是：merge，建议进入游戏，产生一个新版本（v0.12、v0.13……）。不：它留在你的分支上，你可以修改。

  5. Senza Pull Request il tuo ramo è vuoto: nel gioco non entra niente di tuo.

    没有 Pull Request，你的分支是空的：游戏里没有你的东西。

La lavagna del prof

Sulla linea rossa le versioni (v0.8, v0.9, v1.0). In blu il fork che parte dalla v0.9. Sul ramo, le Pull Request: quella accettata (ACCEPT ✓) rientra con il MERGE, quella rifiutata (REFUSE ✗) resta fuori.

Come si chiede una modifica: il giro della Pull Request

Nel vostro gioco funziona come in un'azienda vera. Tu proponi, il programma automatico legge, il prof decide, la versione nuova esce.

你们的游戏像真正的公司一样工作。你提出建议，自动程序读取，老师决定，新版本发布。

  1. Tu scrivi la richiesta nel Modulo «Consegna» (o nel Documento): titolo, cosa cambia, dove, perché. Puoi aggiungere un'immagine.

    你写要求 «Consegna» 在表格里（或文档里）：标题、改变什么、在哪里、为什么。也可以加图片。

  2. Lo script gira da solo ogni 5 minuti: è un programma del prof su Google che legge le richieste nuove e le copia nel repository Git del corso, con il tuo nome e l'ora.

    脚本自己运行 每几分钟一次：这是老师在 Google 上的程序，它读取新的要求，并连同你的名字和时间复制到课程的 Git repository 里。

  3. Il prof (con l'intelligenza artificiale) legge la tua Pull Request e decide: SÌ o NO.

    老师（和人工智能一起）阅读 并决定：是或不。

  4. SÌ = merge: la modifica entra nel gioco, nasce una versione nuova (v1.5, v1.6…) e nel changelog c'è scritto il numero della tua Pull Request.

    是 = merge： 修改进入游戏，产生新版本，changelog 里写着你的 Pull Request 编号。

  5. Tu controlli nel grafo delle versioni: il pallino nuovo è anche merito tuo. Se è NO, leggi il perché, correggi e rimanda.

    你查看 在版本图里：新的圆点也有你的功劳。如果是不，读原因，修改后再发。

Com'è fatta una Pull Request

Quattro parti, sempre, nel Modulo o nel Documento. Esempio vero: la richiesta «Più lento», entrata nel gioco con la v0.3.

总是四个部分。真实的例子：「更慢」的要求，在 v0.3 进入了游戏。

ParteEsempio
Titolo
标题		Più lento
Cosa cambia nel gioco
游戏里改变什么		il treno va più piano: la velocità passa da 1 a 0,7
Dove
在哪里		in tutto il gioco, dall'inizio
Perché
为什么		il gioco andava troppo veloce e non si riusciva a colpire i cattivi

Gli errori della settimana scorsa (e perché)

  1. Mandare solo un file, senza scrivere la richiesta. Il prof non sa cosa vuoi: scrivi sempre Titolo, Cosa cambia, Dove, Perché.

    只发一个文件，不写要求。 老师不知道你想要什么：一定要写标题、改变什么、在哪里、为什么。

  2. La foto di una persona vera. Nel gioco pubblico non mettiamo volti di ragazzi (privacy): usa un personaggio disegnato o di un videogioco.

    真人的照片。 公开的游戏里不放同学的脸（隐私）：用画的人物或游戏里的人物。

  3. Scrivere fuori dal Modulo o dal Documento (una chat, un altro file). Il prof non lo vede: non diventa un pallino del tuo ramo.

    在表格或文档以外的地方写（聊天、别的文件）。 老师看不到：它不会变成你分支上的圆点。

  4. Tutto in un unico testo, senza PR1, PR2. Ogni proposta deve avere il suo numero: PR1, PR2, PR3…

    所有内容写在一起，没有 PR1、PR2。 每个建议都要有自己的编号：PR1、PR2、PR3……
